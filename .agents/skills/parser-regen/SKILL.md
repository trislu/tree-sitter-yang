# tree-sitter-yang parser regeneration

Grammar changes to `tree-sitter-yang` must go through the generator — the
generated artifacts are never hand-edited.

## Parameters / paths

Commands below run from the **repo root** — the directory containing
`grammar.js` (this bundle lives at `<root>/.agents/skills/parser-regen/SKILL.md`;
the former `.github/skills` Copilot edition was archived to the workspace's
`copilot-backup/`). No absolute paths are hardcoded.

- `<grammar-repo>` — root of this `tree-sitter-yang` checkout (`cd` into it first).
- `<yrepo>` — the sibling `yrepo` checkout used for verification
  (`../yrepo` relative to this repo).
- `<corpus>` — a YANG module tree for the whole-tree audit, always supplied
  explicitly. The workflow never assumes where the corpus lives relative to
  the repos; from `<yrepo>`, `scripts/audit.sh --corpus <corpus>` (or the
  `YANG_CORPUS` env var) and `target/release/examples/inspect <corpus>` are
  the supported ways to name it.

## When to use
- A YANG construct is mis-parsed or collapses a file (e.g. the known
  `max-elements unbounded;` whole-file failure), root-caused in `grammar.js`.
- You touched `grammar.js` for any reason (new statement, token, precedence,
  error-recovery tweak) and must regenerate.

## Layout facts (this repo)
- `grammar.js` — the single source of truth (top declares token strings as
  `const … = 'keyword'`, e.g. `const add_arg = 'add'`).
- `src/parser.c`, `src/grammar.json`, `src/node-types.json`, `src/tree_sitter/`
  — generated by `tree-sitter generate`.
- Rust binding is `bindings/rust/` (hand-written `lib.rs` + `build.rs` that
  codegens `NodeKind`/etc from the generated artifacts at compile time).
- Tests are Rust integration tests under `tests/` (no `test/corpus`).

## Steps
1. `cd <grammar-repo>`   # repo root (the directory containing grammar.js)
2. Edit `grammar.js` (follow its existing style: token strings as `const`s,
   reuse the DSL helpers already used in the file).
3. Regenerate. CLI is pinned as a dev-dependency (`tree-sitter-cli 0.26`); make
   sure a matching CLI is on PATH (`cargo install tree-sitter-cli`, or the
   `@tree-sitter/cli` npm equivalent). Then run, from the repo root:
   ```
   tree-sitter generate
   ```
   If the generator also rewrites hand-maintained binding files, re-run with
   `tree-sitter generate --no-bindings` (generated artifacts live in `src/`;
   `bindings/rust/*` is maintained by hand/build.rs).
4. Inspect the diff — it should only touch `src/parser.c`,
   `src/grammar.json`, `src/node-types.json` (plus `src/tree_sitter/*`). If the
   CLI bumped unrelated files (e.g. `.github`, npm lockfiles), revert those.
5. Verify in this repo: `cargo test` (parses the `tests/*` fixtures).
6. Verify through `yrepo` against the real corpus. `yrepo` already carries the
   local override `[patch.crates-io] tree-sitter-yang = { path = "../tree-sitter-yang" }`,
   so no wiring is needed — just re-run the regression:
   `cargo test --features parallel` in `<yrepo>`, then
   `cargo build --release --features parallel --examples`, and probe the
   original failing file:
   `target/release/examples/probe <file>` (whole-tree:
   `target/release/examples/inspect <corpus>`).
7. When green: bump `tree-sitter-yang` version + CHANGELOG, publish, then in
   `yrepo` drop the `[patch]`, bump the `tree-sitter-yang` dependency, run
   tests both feature modes, and sync yrepo CHANGELOG/docs.

## Constraints
- DO NOT hand-edit `src/parser.c` or `src/node-types.json`; regenerate.
- DO NOT commit unrelated regeneration churn; diff before committing.
- DO NOT change generated bindings by hand — `bindings/rust/build.rs` codegens
  from the generated artifacts.
- Keep grammar fixes minimal and RFC 7950-faithful; add a `tests/` case and,
  ideally, note the real-world file it fixes.
- DO NOT bump versions or publish until the user explicitly approves.
